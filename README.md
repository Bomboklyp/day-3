# WorkFlow — День 3

Nuxt 4, TypeScript и Pinia. Основа — второй день. Добавлены изменения заявок, optimistic update, rollback и Undo.

## Запуск

Откройте `start.cmd`, затем http://127.0.0.1:3002/requests/1042.

На другом компьютере с Node.js 24 LTS:

```bash
npm ci
npm run dev
```

## Состояние приложения

| Вид состояния | Что хранится | Где находится |
| --- | --- | --- |
| URL state | Поиск, фильтры, сортировка и страница | Query-параметры, `useRequestQuery` |
| Local state | Открытое окно, текст комментария, выбранный статус до сохранения | `ref` внутри компонента |
| Server state | Заявки, комментарии, история и справочники | API и кэш `useFetch` / `useAsyncData` |
| App state | Настройки, последнее действие для Undo, выполняемые действия и сообщения | Pinia: `preferences` и `request-ui` |

В localStorage сохраняются профиль и настройки интерфейса. Сами заявки остаются на сервере. Undo доступен до перезагрузки страницы.

## Как работают изменения

Статус меняется кнопкой «Изменить статус», исполнитель — выбором в списке. При изменении приоритета интерфейс сразу показывает новое значение и отправляет PATCH. Если запрос успешен, кэш получает ответ сервера. Если произошла ошибка, временное значение удаляется и отображается прежний приоритет.

Pinia хранит только временный приоритет на время запроса. Полные списки заявок в store не копируются.

Для Undo сохраняются номер заявки, изменённое поле и его прежнее значение. Отмена отправляет обратное изменение только этого поля. Комментарии, исполнитель и другие данные сохраняются.

У заявки есть номер версии `revision`. Если данные изменились после их загрузки, сервер возвращает 409. Это предотвращает перезапись чужого изменения. После ошибки можно обновить заявку.

Текст комментария очищается после успешной отправки. При ошибке он остаётся в поле, появляется кнопка «Повторить отправку».

## Основные файлы

- `app/stores/preferences.ts` — профиль, плотность списка и локальное сохранение.
- `app/stores/requestUi.ts` — выполняемые действия, временный приоритет, Undo и сообщения.
- `app/composables/useRequestActions.ts` — запросы на изменение и отмену.
- `app/composables/useRequestCache.ts` — обновление кэша Nuxt.
- `app/components/RequestFeedback.vue` — результат действия и кнопка отмены.
- `server/api/requests/[id].patch.ts` — изменение заявки и проверка версии.

Дизайн: раздел «Уровень 3 · Изменение заявок и обратная связь». Выгрузка 11 кадров находится в `design/figma/level-3.json`. Заявка №1043 «не работает перчик» с описанием «Учебная проверка оборудования» сохранена в начальном наборе.

## Что показать на проверке

1. `/requests/1042` — карточка с исполнителем, приоритетом, комментариями и историей.
2. Изменить приоритет — новое значение и сообщение с «Отменить изменение».
3. Нажать отмену — прежний приоритет восстановлен.
4. Изменить статус — новый статус на карточке.
5. Добавить комментарий — он появился в списке.
6. Открыть `/requests/1042?mutation=500`, сменить приоритет — ошибка и возврат прежнего значения. После проверки убрать `?mutation=500` из адреса.
7. В профиле выбрать компактную плотность, обновить страницу и открыть список — настройка сохранилась.

Для медленного сохранения можно использовать `?mutation=loading`, для демонстрации конфликта — `?mutation=409`. Эти параметры не меняют обычный режим работы.
